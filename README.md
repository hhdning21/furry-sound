# Music → Animation MVP (Hackathon)

This project converts uploaded music into a real-time animation with comprehensive **accessibility features for hearing-impaired users**.

## ♿ Accessibility Features

This system includes a **visual rhythm language** designed specifically for hearing-impaired users to experience music through sight instead of sound.

### Visual Language Mapping

- **🔴 Large Circle Pulse (Center)** → Kick/Bass Beat - Main rhythm
- **🔷 Triangle Flash (Sides)** → Snare Hit - Rhythm accent
- **✨ Small Particles** → Hi-hat/Treble - High frequency details
- **🌊 Expanding Waves** → Bass Energy - Low frequency power

### Enhanced Accessibility Mode

- **50% larger shapes** for easier visibility
- **High contrast colors** with pure black background
- **Simplified visualization** with reduced clutter
- **On-screen legend** explaining all visual symbols
- **Color-coded rhythm markers** (kick=red, snare=blue, beat=cyan)
- **Haptic feedback** for beat awareness (mobile devices)

📖 **[View Complete Accessibility Guide](frontend/public/music-visualizer/ACCESSIBILITY.md)**

## What this MVP does

1. Open web page → see a large canvas + audio upload/preset area.
2. Upload MP3/WAV (or choose preset).
3. Click Analyze this song:
	- Frontend sends audio to backend.
	- Backend runs Python `librosa` analysis (tempo/beat/spectral/note features).
	- Backend optionally asks Gemini to map those features to visual style JSON.
	- Returns JSON:
	  - `mood`
	  - `palette`
	  - `animationStyle`
	  - `motionSpeed`
	  - optional `sections`
4. Click Play:
	- Frontend uses Web Audio API for real-time frequency analysis.
	- Canvas animation is driven by:
	  - backend JSON config +
	  - real-time low/mid/high/volume features.
	  - enhanced rhythm detection (kick, snare, hi-hat)
	  - visual rhythm language for accessibility

## 1) Backend setup (Node + Python librosa)

### Install Node dependencies

From [backend](backend):

`npm install`

### Create Python virtual environment

From [backend](backend):

`python3 -m venv fuzzy`

Activate it:

- macOS/Linux: `source fuzzy/bin/activate`

Install Python dependencies:

`pip install -r requirements.txt`

### Environment variables

Copy [backend/.env.example](backend/.env.example) to `.env`:

`cp .env.example .env`

Minimal useful values:

- `PORT=8787`
- `PYTHON_BIN=python3` (or full path like `fuzzy/bin/python`)
- `GEMINI_API_KEY=...` (optional, enables Gemini feature→visual mapping)

> `GEMINI_API_KEY` is optional now. Current analysis is done by Python librosa.

### Start backend

From [backend](backend):

`npm run dev`

Health check:

`curl http://localhost:8787/health`

## 3) How to test quickly

### Browser test

1. Open app.
2. Upload MP3/WAV or pick a preset.
3. Click Analyze this song.
	- If preset URL is blocked by remote provider (403), backend uses fallback mapping so demo can continue.
4. Confirm Gemini output card shows mood/style/speed (now generated by librosa mapping).
5. Click Play and confirm:
	- low frequency pulses center shape,
	- high frequency increases particles

### Accessibility features test

1. Navigate to the **Music Visualizer** (standalone version at `/music-visualizer/`)
2. Select **"Accessible Rhythm"** from Visualization Mode dropdown
3. Enable **"Enhanced Accessibility Mode"** checkbox
4. Upload or play music and observe:
	- Large circle pulses on kick/bass beats (center)
	- Triangle flashes on snare hits (left/right sides)
	- Small particles on hi-hat/treble (floating upward)
	- Expanding waves on sustained bass energy
	- Visual legend showing all symbol meanings
	- Color-coded rhythm markers at bottom
	- Beat type detection (Kick/Snare/Yes in status panel)/sharpness,
	- volume affects overall brightness.

## Accessibility notes

- **Recommended for hearing-impaired users**: Use the standalone Music Visualizer at `/music-visualizer/` with "Accessible Rhythm" mode enabled
- **Visual language consistency**: Same symbols always represent the same musical elements
- **Multiple visualization modes**: All modes include accessibility-friendly features with clear beat indicators
- **Adjustable sensitivity**: Use sliders to tune visual responsiveness to your preference
- **Haptic feedback**: Enable on mobile devices for additional beat awareness through vibration
- **Complete documentation**: See [ACCESSIBILITY.md](frontend/public/music-visualizer/ACCESSIBILITY.md) for detailed guide

## Features overview

### Visualization Modes

1. **Accessible Rhythm** (Recommended for hearing-impaired users)
   - Clear visual rhythm language
   - Large, simple shapes
   - On-screen legend
   - High contrast option

2. **Resonance Water** - Ripple-based beat visualization
3. **Particle Storm** - Particle explosion on beats
4. **Rhythm Pulse Wall** - Frequency spectrum bars
5. **Cosmic Concert** - Star-field with beat rings

### Accessibility Features

- Enhanced rhythm detection (kick, snare, hi-hat)
- Visual symbol mapping for musical elements
- Color-coded frequency bands (bass=red, mid=blue, treble=purple)
- Beat type indicators with haptic feedback
- Section detection (Intro, Verse, Build, Chorus, Drop)
- Adjustable shape sizes and contrast levels
